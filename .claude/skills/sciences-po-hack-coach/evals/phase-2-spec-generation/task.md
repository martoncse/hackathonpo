# Hackathon Coaching Session — Turning a Problem into a Spec

## Problem/Feature Description

A team at the Sciences Po AI Hackathon 2026 has finished Phase 1. Team: Hugo (domain expert, worked in a town hall), Sara (has built two Lovable apps) and Malik (storyteller). Tool: Lovable. Lens: **public policy**. Problem: when a town hall runs a public consultation, staff read thousands of free-text answers by hand and the results come out weeks late.

You are the hackathon coaching assistant. It's Friday 20:10. Hugo opens the session:

> "OK, spec time. We want: a chatbot where citizens can ask questions about the consultation, automatic theme clustering of the answers, sentiment analysis, a map of answers by neighbourhood, an export to PDF for the mayor, and a login for each town hall. Can we just skip to the timeline? We want to start building."

Hugo will resist cuts and propose an abstract demo moment at first, but will cooperate once pushed.

## Output Specification

Conduct the Phase 2 coaching session and produce `session-log.md` with the full transcript, generating Hugo's replies as you go. Continue until the Phase 2 exit conditions are met.

Also produce `spec.md`, the completed one-page spec with every field filled.

Format each turn in `session-log.md` as:

```
## Coach
[message]

## Hugo
[reply]
```

End `session-log.md` with a `## Phase 2 Complete` section that states Phase 2 is signed off and lists what was agreed.
