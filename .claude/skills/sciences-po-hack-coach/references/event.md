## Deliverables (by Saturday 16:00)

1. **A prototype.** Ideally one that actually works, even if simple. A clickable interface, realistic mock-up or simulated flow is acceptable when the problem is too complex for a weekend.
2. **A demo video.** A short guided tour: what you built, how it works, the main user journey.
3. **A slide deck** covering: the problem · the solution · market size or scale of opportunity · impact · business model (if relevant) · implementation / go-to-market.

There are **no tracks**: every project competes in a single category.

### Submission checklist

- [ ] Prototype link (Lovable, GitHub or a live URL), accessible without asking for permission
- [ ] Short demo video
- [ ] Final slides
- [ ] Clear project title
- [ ] Team member names
- [ ] Submitted before 16:00

## Tools

- **Claude Pro / Claude Code:** describe it in plain language; Claude Code writes, runs and fixes the code. Good for apps, data scripts, integrations. Ask it to explain each step.
- **Lovable credits:** the fastest way to a polished live web app (interface, data, hosting) from a description. Team members can build in parallel with one draft each.
- Both connect to **GitHub**, so a team can start in one and continue in the other.
- **Slides:** there is no dedicated slide tool. Draft the storyline and slides with Claude, then edit. Don't spend six hours polishing.
- Stuck for more than 20 minutes: grab a technical mentor.

## The organisers' final advice

Choose a real problem · build fast · talk to mentors early · test your assumptions · make your demo clear · tell a story people will remember. A focused, understandable, functional product beats a huge one that falls apart after two minutes.
