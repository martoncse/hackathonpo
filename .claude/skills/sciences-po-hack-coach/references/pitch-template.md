# The pitch: opening, 5-minute run of show, video, Q&A

One story, told three times: in the deck, in the demo video, and live in the 5-minute final. Write it once, here.

The mentors preselect finalists from the submission alone, so the video and slides must make the case without you in the room.

---

## A. The opening: three sentences

Juries remember wedges and moments. They forget feature lists. Rewrite each sentence until it is **under 20 words**. Count them.

### Sentence 1 — The wedge

*"Today, when ______ tries to ______, ______ breaks."*

Name a real person at a real moment, and carry one figure.

Good wedges:
- "A third of eligible households never claim the RSA, often because the paperwork stops them."
- "When a town hall gets 2,000 consultation answers, someone reads them by hand for six weeks."

Bad wedges:
- "Public services are inefficient." *(too abstract)*
- "AI will transform the State." *(everyone says this)*

### Sentence 2 — The move

*"We built ______, which ______ for ______."*

One name, one verb, one user. No "AI-powered platform", no "leveraging", no "revolutionising".

### Sentence 3 — The moment

*"Watch this."* → the demo moment from the spec, live or as the video.

Say nothing else before the demo runs. Let the demo be the argument. It must match the spec's **Demo moment** word for word. If they diverge, one of them is wrong: fix it now.

---

## B. The 5-minute run of show

Map it to the six slides the organisers ask for. Spend time where the points are: **deployment is 35%**, the problem only 15%.

| Time | Slide | What you say |
|------|-------|--------------|
| 0:00–0:30 | 1. Problem | The wedge. One person, one figure, one source |
| 0:30–1:45 | 2. Solution | The move, then "Watch this" and the demo moment |
| 1:45–2:15 | 2. Solution (cont.) | Why it's better than what exists today, in one comparison |
| 2:15–2:50 | 3. Market / scale | How many people or organisations could use it, with the source |
| 2:50–3:20 | 4. Impact | What changes if it exists, and the one indicator you'd measure |
| 3:20–4:30 | 5–6. Model + go-to-market | Policy: owner, funding, pilot, timeline, legal and data. Business: who pays, how much, first customers, how you reach the next 100 |
| 4:30–5:00 | Close | The ask, and how it grows after the weekend |

Rehearse with a timer. If it runs over 5:00, cut words, not the deployment section.

**Live demo risk:** have the video ready to play if the live demo fails. Never debug on stage.

---

## C. The demo video (under 2 minutes)

A guided tour of the **main user journey**, not a feature tour. Write it shot by shot before you record.

| # | Shot | Voice-over (one sentence) |
|---|------|---------------------------|
| 1 | The user and their problem (a title card is fine) | |
| 2 | The user starts the journey in the product | |
| 3 | The AI move happens: what it reads, extracts or does | |
| 4 | The result the user gets, on screen | |
| 5 | What it means for them (time saved, benefit claimed, risk avoided) | |

Record the screen with a voice-over in one take. Re-record once at most. A clear video recorded early beats a polished one made at the last minute.
